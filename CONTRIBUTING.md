# Contributing to Docker MCP Server Guide

Thank you for your interest in contributing! 🎉

## How to Contribute

### Reporting Issues

- Check if the issue already exists
- Use a clear, descriptive title
- Provide steps to reproduce
- Include your environment (OS, Docker version, Node version)

### Suggesting Enhancements

- Open an issue with the `enhancement` label
- Describe the use case
- Explain why it would be useful

### Pull Requests

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/amazing-feature`)
3. Make your changes
4. Test your changes
5. Commit (`git commit -m 'Add amazing feature'`)
6. Push (`git push origin feature/amazing-feature`)
7. Open a Pull Request

## Guidelines

### Code Style

- Use TypeScript for all server code
- Follow existing patterns in the codebase
- Use meaningful variable and function names
- Add comments for complex logic

### Documentation

- Update relevant documentation
- Use clear, concise language
- Include code examples where helpful

### Commits

- Use clear commit messages
- Reference issues when applicable

## Adding Examples

If you want to add a new example MCP server:

1. Create a new directory under `examples/`
2. Include all necessary files (package.json, tsconfig.json, Dockerfile, src/, README.md)
3. Test that it builds and runs correctly
4. Update the main README.md to reference your example

## Questions?

Open an issue with the `question` label.
